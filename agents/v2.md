This file is intentionally **untracked** (see `.gitignore`). It holds design notes
and ideas for future phases and releases — the "V2 and beyond" wishlist. Keep it

## Satellite detail link-out

- Currently we do **not** render a link-out on a satellite's detail panel.
- Originally we considered linking to CelesTrak's SATCAT record page:
  `https://celestrak.org/satcat/records.php?CATNR=<noradId>` (a stable,
  deterministic per-NORAD URL).
- **Decision:** we don't want to rely on CelesTrak as the primary link target.
  Prefer an "official" source per object where possible:
  - ISS → NASA / ISS national-lab page
  - Hubble → NASA / STScI page
  - NOAA satellites → NOAA / NESDIS
  - Landsat → USGS / NASA
  - MetOp → EUMETSAT
  - Tiangong → CMSA
  - etc.
- Open item: how to store per-satellite official URLs (a curated map keyed by
  NORAD id in the catalog is the natural home). Keep the CelesTrak record URL
  as a useful fallback for objects without a curated official link.

## Ranking / "interestingness"

- Earlier direction: a weighted "interestingness" score (notability, elevation,
  distance).
- **Pivot:** for V1 we rank purely by what is most visible / closest right now
  (elevation desc, then range asc). No magic weights or fake visual magnitudes.
- Future ideas (post-V1):
  - Illumination / sunlight on the satellite (needs Sun position + phase angle).
  - Upcoming-pass detection ("coming soon" section).
  - Angular movement rate.
  - Real brightness estimate — only if we can source reliable magnitude data
    (do NOT fabricate it).

## Two-view dashboard

- V1 phase 7 added a segmented toggle:
  - **All tracked** — the full curated catalog (browse + tap for detail).
  - **Visible now** — only above-horizon objects, ranked by visibility.
- Future: third view / richer "coming soon" timeline, cloud/weather overlay,
  Moon, planets, stars.

## Location (V1 = opt-in + manual)

- V1 phase 8 made location fully **opt-in**: no prompt at boot; "Use my
  location" (GPS) or "Enter location" (curated city list OR raw lat/lon).
- Future:
  - **Free-text place search** (geocoding) — deferred: keep coordinates generic;
    any query string must not leak a precise position.
  - **Granularity** choice (e.g. precise vs city vs country) — deferred; V1 keeps
    GPS = precise, manual = coarse.
  - "Remember location" as a user preference (would need careful privacy review
    — no precise coords in storage).
  - Show location as text (e.g. nearest city) rather than raw decimal coords.

## FLAGGED — iOS status/address-bar dark overlay (OPEN — parked & documented, 2026-08-31)

- **Symptom (iPhone only):** a dark overlay / scrim sits over the web content in
  the iOS **status-bar region** at the very top of the screen, darkening what's
  below it (header / sky). The web build is unaffected. It is the one thing my
  friend's app doesn't have and I'd prefer gone.

- **What has been tried (chronological), each confirmed not to be the fix or
  reverted:**
  1. `position: fixed` backdrop overlays (star field + grain) — my phone showed a
     band; suspected the fixed layer.
  2. Moving the star field + grain onto the **scrolling `html`/`body` background**
     — removed the seam, but I did **not** want the sky to scroll with content.
  3. Restored the **fixed** backdrop AND set the `html` canvas colour to the sky —
     overscroll top/bottom is now fixed and matches; the remaining dark strip was
     re-attributed to the status-bar region.
  4. **Top safe-area padding** (`env(safe-area-inset-top)`) on `.dashboard` —
     removed; the strip sits *above* the header, not on it.
  5. **Removing `viewport-fit=cover`** — reverted; a misdiagnosis, cover is needed
     for edge-to-edge and is not the cause.
  6. **iOS 26 "Liquid Glass" hypothesis:** Safari tints the translucent
     status/address bars by sampling a `position: fixed`/`sticky` edge element's
     `background-color` (apple dropped `theme-color`). Our two fixed backdrop
     layers were **transparent**, so Safari sampled semi-transparent pixels → dark
     scrim. Attempted fix: **consolidate** the two fixed layers into one
     `body::before` with a **solid `background-color: var(--color-bg)`** + both
     star & grain as layered `background-image`s → **still not confirmed fixed on
     device**, so NOT merged to `main`.

- **Current state / next steps:** issue stays **OPEN**. The solid-background
  consolidation (branch `style/ios-statusbar-fix`) is the best hypothesis but
  needs device confirmation. If it still fails on the phone, next to try:
  - Prove the fixed edge layer is the trigger by removing the fixed backdrop
    entirely (fall back to a scrolling or `html`-only background / a
    background-attachment approach) and re-test on the device.
  - Narrow which bar (status vs address) the overlay tracks with during scroll.
  - Build a minimal replica with and without any fixed edge layer to confirm the
    sample source.
- **Merge policy:** do **not** squash `style/ios-statusbar-fix` into `main` until
  the overlay is confirmed gone on my device.

## Privacy (unchanged principle)

- Precise coordinates stay in the browser; never sent to any backend.
- Keep the proxy stateless; no accounts, auth, DB, or analytics for V1.
